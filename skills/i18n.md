# i18n rules

- Library: `next-intl`. Locale prefix in URL for every locale (`/en`, `/fr`, ...).
- Every string a user can see or a screen reader can read goes in
  `messages/<locale>/<namespace>.json` — labels, buttons, placeholders, alt text,
  aria-labels, toasts, validation errors, meta title/description.
- Namespace per feature/brand, not one giant file: `common.json`, `nav.json`,
  `product.json`, `checkout.json`, `brand-balmain.json`, ...
- Component rule: if you're about to type a quoted string inside JSX that a user
  would read, stop — add the key to the locale file and call `t('key')` instead.
- Pluralization/interpolation via ICU message syntax (next-intl supports it
  natively) — don't hand-roll `count === 1 ? ... : ...` string concatenation.
- Dates, currency, numbers: use `next-intl`'s `useFormatter` (wraps `Intl`), not
  manual formatting.
- New locale = add a `messages/<locale>/*.json` set; no code changes required if
  every string was already externalized.
